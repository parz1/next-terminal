# Next Terminal（暂定名）

自用优先的 Rust 原生终端，先在 macOS 上做出日常可用的基础功能，再根据实际工作需要扩展为未来公司／工作室的开发与运维工具。减少对付费工具的依赖，同时控制开发与维护成本。当前不以教学演示或商业差异化为目标。

## 当前状态（2026-11-05）

已经实现并在本机验证：

- GPUI 原生窗口，不使用 WebView。透明标题栏让终端背景延伸到窗口顶部，标题居中显示当前目录和 shell 名称，窗口标题同步更新。
- 界面分为标题栏、终端网格、命令框卡片和状态栏四层，颜色、字体和尺寸统一来自 `src/theme.rs` 的暖石墨主题；界面文字用系统字体，终端用等宽字体。
- 底部独立的单行命令框卡片：当前目录、快捷键提示、可编辑命令行和执行按钮，聚焦时描边转为琥珀色。支持鼠标定位／拖选、方向键、Shift 选择、整字退格、Home/End、Cmd+A/C/X/V 和长命令横向滚动。
- 状态栏左侧以色点和文字显示会话状态，右侧显示历史回看位置、可用时的“恢复命令框 ⇧⌘E”按钮和网格行列；出错或退出时显示原因。
- 会话状态、输入模式与键盘焦点分开管理。启动阶段保持普通终端；本机 zsh 通过独立控制通道确认空主提示符后自动展开命令框，不能仅凭 PTY 启动或提示符文字授权。
- 自动模式下，每次完成空主提示符确认只允许提交一次。草稿成功入队后清空并收起编辑区，前台交互结束、重新确认空主提示符后自动恢复。Esc／Cmd+Shift+E 主动交出命令框会保留草稿并暂停自动恢复；再次 Cmd+Shift+E 可恢复自动模式。没有集成的 shell 保留手动确认路径。
- 关闭中、已退出、错误和尚未启动的会话阻止命令提交与键盘／粘贴写入；编辑模式下将焦点移到输出区不会把草稿输入转发到 PTY。
- 通过 portable-pty 启动账户默认登录 shell，本机为 `/bin/zsh`。使用账户配置，不受父进程 `SHELL` 覆盖影响。
- 持续读取真实输出，使用同一个 Alacritty 解析器更新字符网格，再由 GPUI 实时绘制。
- 账户默认 shell 为 zsh 时，启动后自动加载内嵌的 `scripts/zsh-integration.zsh`，通过 preexec／precmd hook 发送 OSC 133 通知；首次提示符即显示通知，无需手动 source。使用会话私有临时启动文件，不修改用户配置，通知不改变输入权限。其他 shell 保持原有启动方式。
- 会话私有 Unix socket 通过随机令牌握手，将 shell 控制消息与 PTY 输出分开；带请求号和输入代次的 CHECK 由 ZLE 检查。过期／重复回复、非空编辑行、续行、备用屏幕和失效会话不能授权；查询超时保持直接输入，不向密码或 Vim 的输入流发送探测按键。
- 通过 ZLE 的上下文和缓冲区空／非空通知区分主提示符、续行和其他编辑上下文。提示符开始绘制、行编辑结束和前台命令运行是独立状态；写入 PTY 后先撤销旧观察，等待 shell 更新。OSC 只用于观察，输入授权走独立通道。
- 普通字符、回车、退格、Tab、方向键、Home/End/Delete、基础 Ctrl 组合键的编码与转发。
- 在窗口里输入 `ls` 查看真实文件列表，返回提示符后继续输入；已实际检查退格修正 `pwd`、Ctrl+C 中断前台 `sleep`。
- `exit` 后回收 shell，窗口保留最后屏幕并显示退出状态。
- 系统关闭按钮及 Cmd+W/Cmd+Q 先请求后台清理 shell，再关闭窗口。已验证前台运行 `sleep` 时 Cmd+W 退出后，应用、shell 和该次 sleep 均不存在。
- 颜色、中文双格输出和组合字符；粗体、斜体、下划线、波浪线、删除线、反显和暗色。程序通过 OSC 4/10/11/12 改写的颜色优先于主题。
- 网格按“布局计划 → 绘制”两步渲染：同一行里样式相同的连续字符合并为一段排版，连续中文按两格宽合并，默认背景不画矩形；所有段对齐到主等宽字体的基线，中英文混排不再上下错位。
- 光标聚焦时为实心块并反色显示格内文字，窗口失焦为空心框；遵循程序请求的竖线／下划线形状（DECSCUSR），命令框编辑时隐藏。
- zsh 集成在每个提示符前通过 OSC 7 报告当前目录（按字节百分号编码），标题栏和命令框随 `cd` 更新；OSC 7 只用于展示，不参与输入授权。从 Finder／Dock 启动时进程目录为 `/`，shell 改从家目录开始。
- 中文输入法：命令框和直接终端模式都接入平台输入法接口。拼音以带下划线的组字文字显示在插入点（命令框内联，终端叠加在光标处），候选框跟随插入点；选词后上屏。组字中的 Enter、Esc、退格由输入法处理，不会提交命令、切换模式或删除 shell 中的字。直接终端模式下可见字符先交给输入法，上屏文本与普通按键一样经输入权限检查后写入 PTY；回车、方向键和 Ctrl／Alt／Cmd 组合仍直接编码。长按重复的字符直接写入，避免 macOS 弹出重音字符菜单。
- 根据窗口可用区域计算行列数，同时更新 Alacritty 网格与 PTY 尺寸；shell 接收尺寸变化通知，已有长行随列数重排。
- 鼠标左键拖选可见网格并高亮，Cmd+C 将选中文字复制到系统剪贴板；没有选区时不改动剪贴板。
- 终端直接交互时，Cmd+V 按当前模式处理 bracketed paste 和换行；独立命令框只接受单行纯文本，拒绝换行与控制字符并提示。
- 滚轮和触控板事件可以回看最多 1000 行历史，状态栏显示距离底部的行数。历史视口支持拖选复制；向 PTY 输入、提交或粘贴时自动返回底部。

当前限制：

- 历史最多保留 1000 行，尚无滚动条、历史搜索或磁盘持久化。备用屏幕中的全屏程序暂不处理滚动、鼠标协议或滚轮转方向键。
- 自动恢复仅验证本机 zsh。控制通道使用 zsh/net/socket 和 ZLE fd handler；用户配置覆盖 hook 或模块不可用时可能无法集成，保留普通终端与显式手动确认。随机令牌和私有目录用于避免把普通输出当控制消息，不是同一用户下恶意进程的安全隔离。嵌套 shell、SSH 和复杂插件组合尚未验证。查询等待最多约 700ms，期间用户输入会让旧回复失效；当前使用 PTY worker 的短间隔轮询，尚未做空闲功耗／高负载压力测量。
- OSC 提示符通知仍可被前台程序伪造，因此只显示观察状态。没有独立集成时的手动确认仍是用户对空主提示符的声明，不能检测隐藏密码提示或所有前台程序。
- 输入法组字流程在 Linux 的 fcitx5 拼音上实测（与 macOS 共用 GPUI 的输入法接口实现）；macOS 拼音／双拼、候选框位置与 press-and-hold 行为仍需本机确认。直接终端模式只把组字显示为光标处的叠加层，不支持输入法查询或修改 shell 中已有的文字（例如重新转换已上屏的字）。
- 尚无命令框多行编辑、补全、历史同步或撤销／重做。当前目录只在集成的 zsh 中跟随 `cd`；其他 shell、SSH 和嵌套 shell 显示启动目录。没有按词／按行选择、矩形选择、拖选自动滚动或多会话。调整行列数时清除终端选区。
- 已实际检查普通输入、回车、退格和 Ctrl+C；其他特殊按键已接入映射，尚未逐项在真实程序中验证。Option 组合键和扩展键盘协议未完整覆盖。
- 已转发 Alacritty 的 `PtyWrite` 查询回复；颜色查询、程序通过 OSC 52 访问剪贴板和像素尺寸查询尚未处理。
- 平台相关代码仅支持 macOS。本轮界面改动在 Linux 容器中临时放宽平台门限后截图验证，透明标题栏拖动、红绿灯位置和 Retina 观感仍需在 macOS 本机确认（见验证记录）。
- 只有一套深色主题，尚无浅色主题、字体与字号设置；主题已集中为全局令牌，设置页接入时只需替换 `Theme`。
- 强制杀死应用、特殊启动脚本、主动脱离会话的后台进程，不在当前退出清理保证范围内。

## 运行

需要 Rust 和完整 Xcode／Metal 工具链。在项目目录执行：

```sh
cargo run --locked
```

窗口先启动默认 shell。本机 zsh 集成完成并确认空主提示符后，命令框自动展开、获得焦点。Enter 或右侧按钮提交命令，随后立即收起编辑器，把键盘交给 shell／前台程序；普通命令结束、Ctrl+C 取消或退出 Vim 后，真正回到空主提示符并通过独立 CHECK 才恢复命令框。未闭合引号产生的续行、密码式输入和 vared 等场景保持直接交互。

Esc 或 Cmd+Shift+E 从命令框切到普通终端会保留草稿，并锁定直接交互；执行命令后不会抢回焦点。回到空主提示符时，再按 Cmd+Shift+E 或点击状态栏的“恢复命令框”，重新检查后恢复原草稿。其他 shell 或集成缺失时，仍可以在用户确认空主提示符后手动启用命令框。

鼠标左键拖选终端输出后按 Cmd+C 复制，点击命令框后 Cmd+V 粘贴；命令框内的 Cmd+C/X/V 操作其自身选区。Cmd+C 不发送中断，直接交互时 Ctrl+C 仍用于中断前台程序。关闭窗口使用系统关闭按钮或 Cmd+W。没有自动执行演示命令。

在网格区域向上滚动查看历史，向下滚回底部。复制不会跳回底部；直接交互时输入／粘贴或从命令框提交会回到底部。回看期间有新输出时，在历史容量范围内保持正在阅读的内容。编辑模式隐藏终端光标，避免两个活动光标同时出现。

独立命令框拒绝多行粘贴，不会悄悄拼接或执行多条命令。普通终端直接交互仍保留原有粘贴行为：本机 zsh 启用 bracketed paste 时，多行文本留在 zsh 编辑区，按回车执行；未启用该模式时换行可能立即执行。当前只粘贴文本，不处理图片或文件列表。

### 验证 shell 通知

直接运行 `cargo run --locked`。本机默认 zsh 的首次主提示符确认后会自动展开命令框。可以按完整工作流检查：

1. 连续提交 `ls`、`pwd`、`echo AUTO_OK`，每次执行后恢复空命令框。
2. 提交 `stty size; sleep 30`，运行时命令框收起，行列与 PTY 一致；Ctrl+C 后恢复。
3. 提交 `echo '` 进入续行，普通终端输入继续工作，Ctrl+C 返回主提示符后恢复命令框。
4. 提交 `read -rs reply`，输入临时字符串再回车；没有回显，结束后恢复。不要使用真实密码做测试。
5. 提交 `vim -Nu NONE -i NONE -n`，正常操作并 `:q!` 退出，命令框随后恢复。
6. 写一段未提交草稿后 Esc，直接执行命令，确认不会自动展开；Cmd+Shift+E 恢复后草稿仍在。

需要观察原生 ZLE 输入时先 Esc 暂停自动模式：空格也属于已有输入，Ctrl+U 清空；`echo '` 产生 PS2 续行，续行当前行为空不代表整个命令为空。详细架构与授权规则见 [命令框架构](docs/architecture.md)。

加载方式：创建私有临时目录，将集成脚本和临时 `.zshenv` 写入其中；PTY 仍按账户默认登录 shell 启动。临时 `.zshenv` 在读取用户原有 `.zshenv` 前恢复原始 `ZDOTDIR`（包括原本未设置的情况），此后的 `.zprofile`、`.zshrc`、`.zlogin` 和 `.zlogout` 继续由 zsh 自己按正常顺序读取。一次性 precmd hook 在首个提示符加载集成后移除自身；集成脚本编译进二进制，不依赖启动目录。会话退出或启动失败后清理临时目录。正常退出已验证，强制杀死应用可能留下临时文件。

不会写入用户 dotfiles，恢复后的 `ZDOTDIR` 也不会让嵌套 zsh 继承临时配置目录。仅对 zsh 自动启用；嵌套／远程 shell 的自动集成不在本轮范围内。用户配置若关闭 RCS、覆盖 precmd hook，或系统 `/etc/zshenv` 改写临时 `ZDOTDIR`，可能不加载集成，状态栏显示“shell 状态未知 · 可手动确认”，普通终端输入仍可使用；未验证所有自定义启动框架。系统 `/etc/zshenv` 在恢复前会看到临时 `ZDOTDIR`。也可手动 source 项目中的 `scripts/zsh-integration.zsh` 重新安装 hook。

命令生命周期继续使用 [OSC 133 的 A／C／D 标记](https://iterm2.com/documentation-escape-codes.html)。编辑行通过 [ZLE 的 CONTEXT／BUFFER 和 line-init／line-pre-redraw／line-finish](https://zsh.sourceforge.io/Doc/Release/Zsh-Line-Editor.html) 观察：`start` 是 PS1，`cont` 是 PS2；再加上 precmd／preexec 周期约束，避免把前台程序的行编辑当作 shell 主提示符。使用项目私有通知 `OSC 777;next-terminal;zle;1;start|cont;1|0`（1 表示当前缓冲区为空），以及 inactive／other 标记。通知不包含缓冲区文字，不改 PS1／PS2 或按键绑定。ZLE hook 经 add-zle-hook-widget 注册；本机 bracketed-paste-magic 在等待下一按键前不触发 pre-redraw，因此追加保留原列表的 paste-finish 回调补报空／非空。未验证所有自定义粘贴／编辑插件或 ZLE 挂起场景。同一份原始 PTY 字节分别交给通知观察器和 Alacritty：前者只提取通知，后者继续处理字符网格，避免切割字节影响 UTF-8、颜色与光标控制。观察器使用依赖中已有的 VTE 解析器，不新增协议依赖。

若构建报 `missing Metal Toolchain`，安装 Xcode 官方组件后重试：

```sh
xcodebuild -downloadComponent MetalToolchain
```

## 实现

独立的 [GPUI Kit 设置页样板](experiments/settings-preview/README.md) 已完成字体、字号、主题和固定文本实时预览的原生验证。样板使用独立 Cargo workspace／锁文件；Kit 0.8.0 的组件不能直接插入当前 GPUI 0.2.2 的元素树，主终端尚未迁移，也未接入设置联动。运行方法和负向兼容性探针见样板说明。

| 文件 | 职责 |
|---|---|
| `src/main.rs` | GPUI 应用与窗口入口，注册全局主题、透明标题栏 |
| `src/theme.rs` | 设计令牌：界面颜色、ANSI 调色板、字体、尺寸，以及颜色混合工具 |
| `src/grid.rs` | 网格布局计划（背景条合并、文字段合并、光标）与 GPUI 绘制；布局部分为纯函数并有单元测试 |
| `src/keys.rs` | 按键、粘贴和滚轮到终端字节／行数的转换，以及哪些按键交给输入法 |
| `src/ime.rs` | 直接终端模式的输入法组字状态与 UTF-16／UTF-8 偏移换算 |
| `src/chrome.rs` | 状态色调、家目录缩写等界面外框的展示规则 |
| `src/pty.rs` | macOS PTY、有序输入／尺寸／控制请求、共享输入代次、条件提交和生命周期；保留旧的采集函数 |
| `src/screen.rs` | 网格尺寸计算、Alacritty 屏幕初始化、诊断与解析／重排测试 |
| `src/view.rs` | 组合标题栏、网格、命令框与状态栏；连接输入控制与 GPUI 焦点／布局、PTY 写入、持续解析、尺寸同步和关闭处理 |
| `src/shell_observer.rs` | VTE 流式解析 OSC 133、OSC 7 与私有 ZLE 通知，保存观察状态和当前目录；不参与输入授权 |
| `scripts/zsh-integration.zsh` | 当前交互式 zsh 的生命周期、ZLE 与粘贴 hook；报告命令状态、编辑上下文、空／非空和当前目录 |
| `src/zsh_startup.rs` | 会话私有启动文件、恢复用户配置目录、首个提示符加载内嵌脚本与临时文件生命周期 |
| `src/input_control.rs` | 会话生命周期、自动／普通终端选择、CHECK 请求与一次授权、键盘／粘贴路由 |
| `src/shell_control.rs` | 独立控制协议、随机令牌握手、Unix socket、有界解析、请求超时和断线通知 |
| `src/editor.rs` | 独立单行文本状态、编辑操作、原生文本／组字接口、鼠标选择与横向滚动 |
| `tests/interactive_pty.rs` | 真实 shell 连续输入输出、尺寸通知与退出回收测试 |

命令编辑链路：`GPUI 原生文本输入 → 编辑器草稿 → 显式提交 → 现有 PTY 输入队列 → 同一个 shell`。提交时按当前 bracketed paste 模式封装文本，再发送回车；草稿成功入队后清空并消费本次确认，键盘焦点转到终端。命令框展开／收起会重新计算可用网格和 PTY 尺寸。

InputControl 保存 Starting、Unknown、PromptConfirmed、PromptReady、CommandSubmitted、Closing、Exited、Failed，以及 Direct／Composer 输入模式和用户是否允许自动恢复。OSC 只供 ShellObserver 显示；独立控制通道报告空主提示符后，InputControl 才创建 CHECK。zsh 的 ZLE fd handler 重新检查 CONTEXT、BUFFER、PREBUFFER、PENDING、KEYS_QUEUED_COUNT 和粘贴处理状态；回复必须匹配当前请求和所有 Input 克隆共享的输入代次。提交时在共享锁下比较代次并原子入队，成功后消费授权。所有 PTY 写入（包括查询回复）都推进代次，焦点不能授权。断线、超时、普通终端锁定和生命周期边界均回退或保持直接输入。

直接交互链路继续保持：`GPUI 按键 → 后台写入 → PTY → 默认 shell / 前台程序 → PTY → 有界输出通道 → Alacritty → GPUI 绘制`。

编辑器基于 GPUI 0.2.2 官方 examples/input.rs 改编（Apache-2.0，许可见 licenses/GPUI-APACHE-2.0.txt），原生文本接口需要处理 UTF-16 范围，而 Rust 字符串使用 UTF-8；整字移动与删除使用 unicode-segmentation 的字素边界。没有引入额外编辑器框架。

阻塞读写放在后台线程，UI 每批处理最多 64 块输出，并将刷新合并到约 16ms 间隔。持续保留同一个解析器，避免 UTF-8 或控制序列跨块时丢失状态。

绘制分两步：`grid::layout` 把 Alacritty 网格整理成背景条、文字段和光标，`grid::paint` 再交给 GPUI。文字段内每个字形用 `shape_line` 的 `force_width` 强制按格宽（中文按两格）排列，因此字体回退也不会让后续字符偏离网格；组合字符无法逐字形对齐，单独定位。空格和样式变化会切断文字段，下一段从网格列重新定位。整屏绘制调用的对比数据见验证记录。界面布局与网格行列计算共用 `theme::Metrics`，保证 PTY 尺寸与实际绘制一致。

窗口尺寸变化时，扣除标题栏、状态栏、网格留白和（编辑时的）命令框卡片，用实际等宽字体宽度和主题行高计算完整格子数；行列不变时跳过尺寸更新。行列变化后，UI 更新 Alacritty 网格，并通过与输入共用的有序队列，让后台调用 PTY 的 `resize`，由系统通知 shell。状态栏显示当前列数 × 行数。

拖选将鼠标位置换算为网格坐标和格子的左／右半边，交给 Alacritty 管理选区并提取文本，避免自行拼接时重复宽字符或把自动折行误作换行。Cmd+C／Cmd+V 通过 GPUI 的 [ClipboardItem](https://docs.rs/gpui/0.2.2/gpui/struct.ClipboardItem.html) 访问系统剪贴板；粘贴字节仍走现有 PTY 输入队列，不另开执行命令的通道。

历史内容继续由 Alacritty 保存，滚动只改变它的 `display_offset`，不会向 shell 写入滚轮字符。GPUI 将按行和按像素的滚动统一换算为行数，保留不足一行的余量；绘制、高亮与拖选统一用该偏移转换坐标。输入时将视口滚回底部，PTY 尺寸和 shell 状态不受回看操作影响。

## 接下来

接下来按完整功能闭环推进：在 macOS 本机确认中文输入法体验后，完善常用按键／选择／历史操作。外观设置联动需要先决定主窗口与 GPUI Kit 的版本迁移策略；当前设置页仍是独立样板。先设计清楚边界再实现和验证，不再按每个实现细节拆分轮次。

SSH、SFTP、按客户／项目整理环境以及同事交接是未来候选，尚未实现；Agent、MCP、插件、账号和同步暂不在范围内。独立命令编辑器已经按新的方向实现最小版本，补全、历史同步和输出分块仍未实现。

[Next Shell](../next-shell/README.md) 是独立 shell 实验，当前终端使用系统已有 shell，不与 Next Shell 共享私有协议或强制绑定。
